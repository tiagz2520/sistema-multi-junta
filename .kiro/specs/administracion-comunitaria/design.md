# Diseño de administración comunitaria

Todas las rutas cuelgan de `/api/v1/juntas/:juntaId/administracion`. El servidor compara el UUID con la sesión y establece junta y huella verificada en una transacción Prisma. Las tablas tienen `junta_id`, claves compuestas, RLS forzada y permisos explícitos. Una sola serie de escrituras por junta protege operaciones que atraviesan administración, recursos y finanzas. La cédula usa diez dígitos ASCII y unicidad por junta. No se usa para unir cuentas o para acreditar identidad civil.

| Recurso                                                | Contrato                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sectores`                                             | GET/POST y GET/PATCH `/:id`. `{nombre, clasificacion, descripcion?, estado?}`. GET `/:id/socios` lista integrantes. Administración escribe y Secretaría consulta.                                                                                                                |
| `socios`                                               | GET con `q`, `estado`, `sectorId`, `offset`, POST y GET/PATCH `/:id`. `{cedula, nombres, apellidos, sectorId?, estado?}`. Registro, edición y baja por Secretaría. Administración y Tesorería tienen consulta.                                                                   |
| `actividades`                                          | GET/POST, GET/PATCH `/:id`. `{tipo: ASAMBLEA/MINGA, titulo, inicio, fin, lugar}`. Fechas ISO con zona. El alta toma una instantánea de socios activos como participantes. GET `/:id`incluye participantes con asistencia e historial. POST`/:id/cerrar` valida todas las marcas. |
| `actividades/:id/asistencias/:socioId`                 | PUT `{estado: PRESENTE/AUSENTE, motivo?}`. Una corrección requiere motivo y guarda la marca anterior.                                                                                                                                                                            |
| `actividades/:id/asistencias/:socioId/justificaciones` | POST `{motivo}` para una ausencia. PATCH `/:justificacionId` `{decision: ACEPTADA/RECHAZADA, motivo}`. La aceptación modifica la asistencia en la misma transacción.                                                                                                             |

Las colecciones devuelven arreglos. Las fichas identifican registros por `id` y nunca incluyen credenciales. Los participantes mantienen su identidad histórica aunque el padrón se desactive. Las nuevas relaciones usan baja lógica y `RESTRICT`. La minga o asamblea cerrada conserva su fecha para determinar la tarifa. Una justificación pendiente no habilita multa. La relación con convocatorias y actas se incorpora con su módulo.
